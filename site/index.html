Why it exists

Measuring a quota should not spend it

Softcap reads subscription usage directly for accounts added through the browser. These requests fetch limits without sending a prompt or running a model.

Codex works the same way: sign in through the browser and Softcap reads that account's usage directly from the service. Nothing is taken from the CLI's own files, so what you see never depends on when Codex last ran.

Several plans

It will not sign your CLI out

Your keychain holds a token only for the plan you are signed into, and refreshing it can rotate that token on the server — signing Claude Code out. A monitor that logs you out of the thing it monitors is worse than none.

So the active account is read-only here, and Softcap keeps its own copy of the refresh token for when you move on with /login. It can only take that copy while Softcap is running, so sign into each plan the ordinary way with the app open — one poll later it is kept, and they stay on screen together. Reading the CLI's keychain item needs macOS's permission, which Softcap asks for when you press a button — never from a timer nobody is watching.

Over time

Three subscriptions, one month, zero spent to know it

One line per account. Colour means which account here and how loaded everywhere else, so the two scales never borrow from each other. The plans renew on different days — so at any hour, the picture says which account is fresh.

The dashed guides are where notifications fire: a nudge at 80%, a last warning at 95%. Every drop is a week's allowance renewing. And a break, like alex's, is a stretch with nothing measured; drawing across it would claim a reading nobody took.

The rest of it

Small things that matter at 2 a.m.

A timer in the menu bar

Whichever limit is closest to running out, and how long until it frees up — without clicking. The strip can carry the countdown, the percentage, both, or just the icon, and a shortcut of your choosing opens the window without reaching for the mouse.

Widgets

All four sizes on macOS; on iPhone the home screen and the lock screen. The same account row the window uses, so they cannot drift apart.

It tells you before you hit it

At 80% and 95% out of the box, or whichever levels you set instead — once per crossing, not once per poll.

Quiet hours

Nothing arrives while you sleep, and nothing is delivered late to make up for it.

Ten languages

Including Arabic, laid out right to left. Switching takes effect immediately, with no restart.

Your tokens stay put

Credentials stay in the keychain, never copied into preferences or logs. When something fails, the app sends a description of the failure to its author, stripped of paths, addresses and anything token-shaped before it leaves the machine — and it can be switched off. The only other request is a check for a new version, daily and while the update screen is open, and that can be switched off too.

Under it

For the sort of person who reads this part

Requires
macOS 14 or later. The iPhone app needs iOS 17.
Claude
Live, from the OAuth usage endpoint. How Claude limits work →
Codex
Live usage for every account, read from the service with that account's own grant. How Codex limits work →
Adding an account
Choose Claude Code or OpenAI Codex, then sign in with OAuth and PKCE in your own browser. Local CLI accounts are also detected.
The core
A Swift package with no AppKit and no human-facing strings. Window, widgets and phone share one row view.
Dependencies
None. Every import is either Apple's own framework or a module of this project.
Cost of running it
One request per Claude account per poll. Five minutes apart in the background, once a minute with the window open — or anywhere between thirty seconds and an hour, if you set it. Claude name and plan are asked once and kept for six hours. Each saved Codex account adds one usage request per poll.
Not yet
Cursor, GitHub Copilot and Gemini CLI. A provider that cannot be checked against a live account would quietly show zero, which is worse than nothing.
